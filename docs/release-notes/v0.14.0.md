# PVArr 0.14.0

Everything in [0.13.0](v0.13.0.md), plus:

- **Sources are back.** Most relays on event pages changed how they deliver video: each segment
  is now a PNG image whose pixels carry ordinary compressed video, and some serve their playlist
  as a JSON list of segments instead of an `.m3u8`. FFmpeg can read neither, so PVArr found one
  working stream at best, or none. PVArr now recognises both by their shape and records them
  through its loopback relay, which unpacks each image and hands FFmpeg plain MPEG-TS. On the
  event page that prompted this, the count went from 0 recordable links to three independent
  sources.
- **More links resolve.** A link whose page refuses PVArr's ordinary HTTP client is fetched again
  with the browser TLS profile already used for playlists, and when a player lists several
  playlists, PVArr picks the first whose video actually downloads.
- **Honest probe.** Pasting a stream whose segments are plain images now says so instead of
  reporting it resolved.

**Cost:** for these packaged sources the video passes through PVArr: a few Mbps on loopback and
one short FFmpeg image decode per segment (about 0.1 s on a desktop, several times that on a
Raspberry Pi). Other sources are unchanged.

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is recording.
No settings change. The API adds `wrapped`/`png_wrapped` and `json_playlist` fields; nothing is
removed.
