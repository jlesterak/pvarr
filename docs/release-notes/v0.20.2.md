# PVArr 0.20.2

Everything in [0.20.1](v0.20.1.md), plus three fixes found on one live recording, where every link the
event page offered played the wrong game except a few that only the browser sidecar could open.

- **The event-page re-check looks past streams you marked as the wrong game.** Links playing a marked
  stream no longer count as found, so the re-check keeps going (browser sidecar included) for one that is
  not marked; the card log counts them ("10 on the wrong game"). When every source of the recording is
  marked, the browser look is as wide as with nothing recording (up to 12 pages, two at a time).
- **Backups only the browser can open are no longer called dead.** The 90-second backup check never uses
  the browser, so it could not find their playlist and marked them "not answering", and failover skipped
  them. They are now left unknown and failover tries them as usual.
- **WebP-wrapped segments with a pad byte are recorded.** A feed that packs MPEG-TS behind a WebP header
  and ends each segment with a stray byte was refused as "segments are images, not video". Up to 16 pad
  bytes after the last packet are now trimmed.

**Upgrading:** nothing to change. The first two fixes matter only with an event page and the browser
sidecar (`PVARR_BROWSER_URL`).
