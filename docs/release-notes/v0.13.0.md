# PVArr 0.13.0

Everything in [0.12.0](v0.12.0.md), plus:

- **Extend a running recording.** Games run long. A running recording's card now has **+15m**,
  **+30m** and **+1h** buttons that push its end out from the current end, and **Edit** to set an
  exact end time (which may also shorten it). The new end is saved, so a restart mid-overtime
  resumes with it. The **Events** tab adds **Keep 0/15/30/60 min after** next to *Start N min
  early*, added to each scheduled game's end (default 0, the old behaviour).
- **Schedules that find nothing look like errors.** A job whose page check found no stream used to
  keep the blue *waiting* badge. It now shows **not listed yet** (amber: the page has no links
  yet, normal before kick-off), **blocked**, **page error** or **no stream** (red). Under it,
  PVArr lists up to five links that failed in a way you can fix by hand, each with what to do
  (a player that builds its link in JavaScript, a host that wants a cookie or referer, a rejected
  token), and **Record manually** opens New Recording with that game and link filled in. **Find 3
  streams** marks the same links *(fixable by hand)*. Notifications never include these links.

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is recording.
No settings change. The API adds `POST /api/recordings/{id}/end`, `miss_kind` and `fixable` on
`/api/schedules` jobs, and `fixable` per link in `/api/aggregate`; nothing is removed.
