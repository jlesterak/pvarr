# PVArr 0.19.0

Everything in [0.18.0](v0.18.0.md), plus:

- **Time without data on the card.** A source that froze and was failed over lost no segment by
  FFmpeg's count, so a recording that froze twenty times still read "0 lost". The card, the finish
  log line and the finish notification (from one minute) now show the time without data: every gap
  of more than 12 s in which the file got nothing new, counted across failovers and reconnects.
- **Stall lengths per source.** When PVArr leaves a source that stalled for 8 s or more, the log
  lists those stall lengths, and a recording ends with one line per source: how many, the median
  and the longest. This is measurement only; the freeze timer behaves as before.
- **One kind of wrong game is caught without you.** When a backup's playlist sits on the same
  provider host and path as the stream already being recorded but carries a different event number
  in that path (`/hls/event-123456/` against `/hls/event-123457/`), PVArr skips it and marks it
  wrong game. The backup check avoids it and the event-page re-check will not swap it in. Dates and
  timestamps in a path never count. **Wrong Game** on the stream that set the number clears it.
- **A Referer that worked is kept.** If a feed delivered data with a Referer and a later connect
  to the same feed finds none (a host that starts requiring one mid-game), PVArr reuses the one
  that worked. A Referer the probe chose is never replaced.

**Cost:** none worth measuring: a few counters per recording, no extra requests.

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is recording.
No settings change.
