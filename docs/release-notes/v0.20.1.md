# PVArr 0.20.1

Everything in [0.20.0](v0.20.0.md), plus one fix. It matters only with commercial detection on
(`PVARR_COMSKIP=1`).

- **Commercial detection survives a restart.** Detection runs after a recording is finished, filed
  and announced, and can take up to an hour. If PVArr crashed or was killed in that time, the recording stayed without chapter marks for
  good; after a clean stop the marking was redone only by accident, and the recording was announced
  a second time. Now the next start runs the detection again, in the background (log: "Commercial detection on ... was interrupted; running it again").
  The recording is not remuxed, moved or announced a second time. A recording whose detection was
  started three times without finishing is left without marks, and the log says so.
- **A shutdown does not wait for it.** Stopping PVArr while only commercial detection is left
  returns at once instead of using the whole `PVARR_SHUTDOWN_TIMEOUT`, and the log no longer says a
  `.ts` was left un-remuxed when the finished file was already in place.
- An unfinished hidden chapter copy left beside a recording by a killed run is removed before the
  redo, and a repeated run does not add a second row to the ad statistics.

**Upgrading:** nothing to change. A recording that lost its marks to a restart before this version
is not picked up; only interruptions from 0.20.1 on are redone.
