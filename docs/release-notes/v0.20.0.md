# PVArr 0.20.0

Everything in [0.19.0](v0.19.0.md), plus:

- **The browser sidecar looks further when nothing is recording.** A Find or a scheduled check with
  nothing recording sends up to 12 unresolved links to the sidecar, two pages at a time, within
  3 minutes (during a recording it stays at 4 links, one page, 45 s). A scheduled recording that
  already has a working link keeps the 45 s limit, so its start is not held back; once a recording
  starts, the look goes on one page at a time so a failover finds a page free.
- **Likeliest link first.** PVArr remembers per link host whether the browser found a playlist
  there (`browser-hosts.json` in the config folder: host names and counts, learned from your own
  results) and asks those hosts first; hosts that keep missing go last.
- **"Blocked by DNS" instead of a silent miss.** On a network whose DNS server answers `0.0.0.0`
  for some hosts (a network-wide blocklist), the sidecar found nothing on pages that play in your
  browser. Those requests are still refused, but the card now says how many hosts were blocked by
  DNS and to give the sidecar another DNS server ([how](../browser-sidecar.md)). Such a miss does
  not count against the link's host.
- **Team-name check (warning only).** When a link's page title names a game and neither of the two
  teams you entered, the source gets an amber **other game?** on the card, one log line and, for the
  stream being recorded, one notification. Nothing is skipped or stopped; **Wrong game** stays your
  call. Titles are shown with every numeral removed, so a score in a title cannot reach you.
- **Low-disk warning before a scheduled recording.** A waiting job shows an amber **low disk**
  line (`disk_warning` in the API) when its length at an assumed 6 Mbit/s, plus the recordings
  before it and `PVARR_MIN_FREE_GB`, exceeds the free space, and you get one notification 20
  minutes before the start if it still does. Nothing is deleted or refused.
- **Notifications no longer delay a connect.** Alerts a recording raises are sent on their own
  thread.

**Cost:** with the sidecar, two pages for up to 3 minutes before a game (measured up to 1.8 GB,
inside the documented 2 GB limit); without it, nothing changes. The low-disk check is a few
`statvfs` calls per dashboard refresh, and only while a job is waiting. One new small file in the
config folder (`browser-hosts.json`, at most about 60 KB).

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is recording.
If you run the sidecar, update both images together (an older sidecar does not say "blocked by
DNS", so PVArr would count those misses against good hosts; delete `browser-hosts.json` if the
sidecar was updated late). On a network with a filtering DNS server, give the sidecar's network
container a `dns:` entry as [docs/browser-sidecar.md](../browser-sidecar.md) shows, then recreate
it and the sidecar. No other settings change.
