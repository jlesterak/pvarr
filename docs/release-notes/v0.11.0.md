# PVArr 0.11.0

Everything in [0.10.0](v0.10.0.md), plus:

- **Events tab.** A new tab (and header button) for pages that list many games. Save the
  pages you use (kept on the server, so every device sees them), pick one to list its
  games grouped live / by day, tick several and schedule them all at once. Each starts
  5, 10 or 15 minutes before its listed time and ends after the league's usual length.
  Already-scheduled, untimed and finished games are marked and cannot be ticked. API:
  `GET/POST /api/event-lists`, `DELETE /api/event-lists/{id}`.
- **Find ranks what it finds.** Up to six working streams are measured (real resolution,
  frame rate, bitrate, and how much faster than real time they download) and the best
  three fill the slots, best first; one that cannot keep up ranks last. Backups come from
  different real feeds where possible, and if the first six are all one feed relayed by
  several sites, Find keeps looking for a different one. `PVARR_RANK_STREAMS=0` keeps
  page order.
- **Re-check when sources die.** A recording started from an event page re-checks it when
  two of its sources fail, and swaps fresh links into the dead slots (never the one
  recording). Also on demand with **Re-check event page** on the card.
- **Picks in the log.** Find, a scheduled start and a re-check each log one line with the
  streams picked, what each measured, and which backups relay the same feed.

Fixes:

- A recording could be finalised mid-event after its third restart in total, however long
  it had run fine in between. The resume limit now starts over once a resume has recorded
  for 10 minutes.
- A listing page on the internet could name a game link into your local network; such
  links are now left out.
- **Force Failover** no longer greys out on the last source; the header no longer pushes
  the page sideways on phones; a re-check that replaced nothing says why.

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is
recording. No settings change. Find now takes longer (about 40-55 s instead of 25-30 s)
because it measures streams; set `PVARR_RANK_STREAMS=0` on a metered connection.
