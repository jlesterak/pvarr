# PVArr 0.10.0

Everything in [0.9.0](v0.9.0.md), plus:

- **Read game.** Next to **Find 3 streams** on the event page box. It reads the page once,
  checks no links, and fills in Sport, both teams, Start at and End at from what the page
  says about the game: schema.org event data, an "A vs B" heading or title, a
  machine-readable start time, or a LIVE label. Team names are matched against the offline
  team list, so they come out spelt the same way every time and the league is filled in.
  End at defaults to a usual game length for the league. A page that links to many games
  shows them as a list, live ones first; click one to fill the form and schedule it.
  Nothing here is site-specific, and a page without these details simply fills in nothing.
  **Find 3 streams** now also fills in Sport and the teams. API: `POST /api/event-info`.
- **`GET /api/health`.** Answers 503 when a session says it is recording but has written
  nothing for `PVARR_WEDGE_SEC` (default 300 s). The image's healthcheck and the compose
  file now use it, so a wedged recording shows as unhealthy instead of hiding behind a
  200 from `/api/status`.
- A rebroadcast channel keeps retrying a dead upstream until it is stopped, instead of
  ending itself after a fixed number of laps.
- hls-proxy is always bound to 127.0.0.1, so an inherited environment variable cannot
  expose it.

**Upgrading:** `docker compose pull && docker compose up -d`, ideally while nothing is
recording. No settings change. If you keep your own copy of `docker-compose.yml`, point its
healthcheck at `/api/health` to get the wedge detection; the old `/api/status` check keeps
working.
